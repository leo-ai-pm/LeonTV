# Leon TV repository guide

- Product: local AI video workspace evolving toward an Agent Harness.
- Application root: `Leon TV/Leon TV/` from this Git repository root.
- Backend: FastAPI/Pydantic/Python; frontend: Next.js/React/TypeScript/React Flow.
- Current execution: fixed six-stage workflow with stage handlers and some local review loops.
- Formal Harness foundation: Studio run-validation panel and `/api/harness/runs` use real private persistence and recovery; actors/media are test fixtures, with zero real model/paid calls. See `docs/HARNESS-RUNTIME-API.md` and `docs/HARNESS-RUNTIME-VALIDATION.md`.
- Creator intake: `/creator` is the default A Screening Room workspace. `/api/creator/briefs` privately persists scripts, requirements and budget drafts with version/conflict recovery. Saving never creates a run or authorizes execution; see `docs/CREATOR-BRIEF-API.md`. Legacy `/workflow` and root session/stage links remain supported.
- Brief planning: `/api/planner` freezes explicit saved Brief revisions into private durable tasks. Normal tasks stay unauthorized; a separate `offline_test` entry exercises the bounded tool/feedback/validation/recovery loop with synthetic model responses. No live authorization route or paid calls; structure validity is not content acceptance. See `docs/BRIEF-PLANNER-API.md` and `docs/BRIEF-PLANNER-VALIDATION.md`.
- Controlled text execution: D09 adds a separate journal bound to immutable D08 source; server quotes/grants, atomic holds/intents/call counts, trusted input bounds, receipt normalization and local pricing. Production stays disabled; synthetic policy/transport checks do not establish real billing or creative quality. D08 source is read-only; see `docs/PLANNER-EXECUTION-API.md` and `docs/PLANNER-EXECUTION-VALIDATION.md`.
- `experiments/harness_poc` is deterministic; `experiments/tudou_ab` is a controlled trial. Neither establishes a full autonomous product Harness.
- Product architecture/status: `docs/ARCHITECTURE.md`; priorities: `docs/ROADMAP.md`.
- User-selected design workflow: UI UX Pro Max for static UI/UX; Emil `animate` and `review-animations` for interaction motion. See `docs/design/DESIGN-WORKFLOW.md`; keep prototypes distinct from delivered production capabilities.
- Visual direction selected by the latest user instruction on 2026-10-20: A, Screening Room (放映室), with dark surfaces and a focus on video preview and review. This supersedes the earlier B selection. Preserve the autonomous task workflow; keep the canvas and six-stage workflow as advanced entries.
- Setup: `docs/GETTING_STARTED.md`; checks: `CONTRIBUTING.md`.
- Backend start: from `Leon TV/Leon TV/backend`, run `uv run python api_server.py` (127.0.0.1:8000).
- Frontend start: from `Leon TV/Leon TV/frontend`, run `npm run dev` (localhost:3000).
- Backend checks: `uv run --extra dev python -m pytest -q`.
- Frontend checks: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- Never print or commit real configuration, credentials, private scripts, signed media URLs or runtime receipts.
- Keep `backend/code/` and `backend/harness_data/` local; publish selected demo copies only under `docs/assets/demos/`.
- Tests must use synthetic authorization and credentials, not private production state.
- Preserve user assets and existing work; inspect changes before editing or committing.
- Preserve upstream copyright/license and compatibility identifiers needed for old data.
- Report code, mocked checks, real model execution, content quality and human acceptance separately.
- Do not restart shared services, generate paid media or publish changes without task authorization.
