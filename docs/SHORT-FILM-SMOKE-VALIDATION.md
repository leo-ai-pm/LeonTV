# 短片模式六阶段冒烟验收（2026-11-05）

范围：验证「创作简报/六阶段」在**短片模式**下能否由产品自身产出竖屏短片，
并记录过程中发现与修复的集成缺陷。

环境：本机单用户 Web（前端 `next dev`、后端 uvicorn），模型全部为真实调用——
DeepSeek `deepseek-chat`（剧本/分镜）、土豆中转 `gpt-image-2-all`（出图）、
土豆中转 `claude-sonnet-5.5`（VLM 看图评分）、土豆中转 `seedance-2.0`（图生视频）、
本地 FFmpeg（后期）。

## 一、为什么要短片模式

首次按默认配置输入「15 秒竖屏短片，2 个镜头」时，剧本阶段按微短剧结构展开：

- 剧本：4 集，每集 25–30 行台词
- 分镜：**20 段 / 48 镜 / 预计 175 秒**

比用户意图大 11 倍，且参考图与视频会各跑 20 次以上。

定位：`prompts/script/generate_script_zh.txt` 是微短剧专用提示词（对话占比 70%、
每集 25–30 行），`script_agent` 没有任何目标时长或镜头数约束；
`storyboard_agent` 的时长按台词字数推算（2–15 秒/段），没有总量上限。

修复（`5fcd10f`）：

- 启动页标注六阶段适用于 1 分钟以上多场次作品，并提供「拍短片？用画布」入口
- 新增短片模式（15 秒 / 1–4 镜），会话记录 `content_mode`、
  `target_duration_seconds`、`target_shot_count` 并加入 `SESSION_META_KEYS`
- 短片剧本改用专门提示词：单集、固定场次、无对白、每场一条 action，
  跳过微短剧的台词/情节评估与删减

修复后同一输入：**1 集 / 2 场 / 6 行 / 无对白**，分镜 **2 段 / 2 镜 / 10 秒**。

## 二、冒烟中暴露并修复的集成缺陷

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | VLM 一律判 0 分并触发无限重生成（10 分钟、6 张图仍未通过） | 中转把图片存成 `.png/.jpg`，实际字节是 WEBP；客户端按扩展名声明 MIME，被上游以「media type 与内容不符」拒绝 | 按文件头识别真实格式（PNG/JPEG/WEBP/GIF），扩展名只作兜底（`7ec4365`） |
| 2 | 参考图产出 2560×1440 横屏 | 启动页短片模式沿用全局 `video_ratio=16:9`；`character_agent` 又把画幅写死 `"16:9"` | 短片模式固定 9:16；角色阶段读取会话 `video_ratio`（`7ec4365`） |
| 3 | 视频阶段全部报「图生视频需要公网参考图」 | 阶段 Agent 改名输出文件时，土豆的 `.tudou-source.json`（厂商公网 URL）留在旧文件名上 | 新增 `move_media_with_provider_source`，改名时同步迁移凭据（`4bb721f`） |
| 4 | 单镜失败导致后期整体失败 `FileNotFoundError: 缺少已选视频片段` | 后期要求所有片段都有文件 | 抽出 `plan_assembly_selection`：缺镜记警告并跳过，全部缺失才报错；产物带 `partial`/`missing_clips`，页面显示「部分出片」（`86c572c`） |
| 5 | 上游 `status=failed` 直接判定失败 | 未区分通道抖动与内容拒绝 | 仅对 `upstream_failed` 按 10s/30s 退避重试 2 次；`submit_unknown`、4xx、`delivery_failed` 不重试（`151012d`） |

### 关于第 5 项的判断依据

同一提示词与参考图连续四次提交：

| 次 | 结果 | 细节 |
| --- | --- | --- |
| 1 | 提交无回执 | 无 task_id |
| 2 | 上游 failed | 23 秒、进度 100% |
| 3 | 上游 failed | 同上 |
| 4 | 成功 | 约 3 分钟，正常出片 |

直接查询中转任务详情只得到 `{"status":"failed","progress":100,"error":{"message":"生成失败，请稍后重试"}}`，
**没有内容策略码或参数错误**。因此判定为通道抖动，而非内容或参数问题。

## 四、验证边界（不作为已验收能力）

1. **内容质量未评审**：成片只做过技术核验，没有人工看片结论。
2. **9:16 不是精确比例**：`gpt-image-2-all` 请求 9:16 实际返回 768×1344（≈0.571），
   与 0.5625 有偏差；视频阶段按 9:16 输出，未验证是否会裁切或补边。
3. **依赖中转通道**：本轮文本与视频端点多次出现 522 / SSL EOF / 503
   （`system cpu overloaded`），重试机制是为该现状设计的，不等于通道稳定。
4. **未覆盖多集、长片、重新生成、人工介入**等路径。
5. 测试只能证明代码路径；真实模型输出的稳定性需要多次运行才能评估。

## 五、复现步骤

1. 配置 `deepseek.api_key` 与 `tudou.api_key`，并把默认模型设为
   `llm=deepseek-chat`、`vlm=claude-sonnet-5.5`、`image_t2i/it2i=gpt-image-2-all`、
   `video_first_frame=seedance-2.0`
2. 打开 `/workflow`，开启「短片模式」，选 2 镜，输入一句创意
3. 点「逐步创作」，按提示逐阶段确认（六阶段保留人工确认点）
4. 若某镜视频被上游判失败，重试机制会自行重提；
   仍失败时后期会以「部分出片」交付已完成部分
