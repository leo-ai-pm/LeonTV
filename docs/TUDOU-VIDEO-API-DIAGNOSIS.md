现有配置 Key 的只读 `/v1/models` 请求返回 HTTP200，不带 Authorization 的同一路径对照返回401；模型列表包含 minimax-h3 和 seedance-2.5。这能确认通用鉴权有效、模型标识被列出，不能证明每个模型的执行通道健康，也不能替代对账户及上游路由配置的检查。

分组下拉框有自动、default、svip、vip 及其他选项。选项的 `aria-selected` 可能只反映键盘高亮，不作为已保存分组的证据；没有据此切换分组。密钥无限配额也不代表账户余额无限。

## 网站示例与实际文档

[模型广场](https://api.ai-tudou.net/pricing)的模型详情 API 标签混用了文本调用模板：H3 给出 `/v1/videos` 加 `messages/temperature`；Seedance 2.5 的示例主机与路径之间还缺少 `/`。这些模板不能直接作为视频接入合同。

从[官方文档中心](https://docs.ai-tudou.net/)进入的[Wan 视频专门文档](https://docs.ai-tudou.net/wan3.0-video-api%EF%BC%88net%EF%BC%89-docs.html)明确使用：

- `POST /v1/videos/generations` 提交；`GET /v1/tasks/{task_id}` 查询。
- JSON 中包含 `model/prompt/duration/aspect_ratio/resolution`，参考图为公网 URL 的 `images` 数组。
- 成功业务 code 为200，ID 可位于 data.id、data.task_id 或顶层；完成结果位于 data.result，失败为 failed 状态。
- 不要重复创建同一任务，完成后应及时下载。

当前文档导航没有提供可直接打开的 H3／Seedance 2.5 专门合同；Wan 的模型时长与参考素材上限不能直接套给它们。模型广场对 Seedance 2.5 的描述为720p、4–30秒、最多30张参考图；H3公告声明支持9张参考图，价格页列出720p规格。这些页面与既有15秒／720p／3图输入没有明显冲突，但不足以确认两模型所有专属字段。因此本轮没有猜改模型名、分辨率、生成入口或新增参考素材。

## 原两次失败的定位

两次真实失败属于上一轮 D21：外层 HTTP502 `fail_to_fetch_task`，消息中含上游 failed、HTTP503 `model_not_found / No available channel`。内部错误中的分组属于上游分发链，不能直接等同于令牌的 default 分组。消息里的上游标识也不是已经确认的本平台任务编号。

可以确认故障到达了供应商上游路由层；未发现 Key 无效、模型白名单或 IP 限制的证据。仍不能从外部回执确定最终原因是渠道被停用、上游无资源，还是供应商的模型／分组／参数映射错误，更不能断言全平台模型已下线或已恢复。

上一轮实际调用使用根冻结的私有控制器，没有经过此次修改的公共客户端。下面的公共恢复缺陷不能作为那两次上游失败的原因，也不能把修复后的合成测试作为通道恢复证明。

## 公共客户端修复

- 同一输出路径的生成和恢复共用文件锁，防止并发重复提交或重复交付。
- 复用已持久化的 completed 结果；以原回执中的文件摘要核对本地交付，缺失摘要的旧文件需重新下载原结果后建立绑定，不能把任意非空文件视为原视频。
- 缓存结果下载返回403／404／410时，只对同一任务作一次只读刷新并最多重试一次下载；保留已确认的完成证据，磁盘错误和普通超时不触发刷新。
- failed／error／expired／cancelled／rejected 回执保持终态，不覆盖后重发或重新查询后降级。
- HTTP成功但业务 code 失败时，不接受其中 ID；保留原合法成功格式。502 和缺失可靠提交回执仍保持 unknown，不从嵌套消息提升上游 ID。
