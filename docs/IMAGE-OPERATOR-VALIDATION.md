## 本轮修复与边界

- 历史媒体scope先按确切policy、anchor、manifest、origin和profile寻找唯一既有记录，再重建历史接受证据并复用出生交接。后续任务或旧文本grant变化不会错误创建另一个scope或复用allocation；新scope仍核验当前完整opening。
- 每次权限校验只读取一次独立原生snapshot，并在该次校验内复用；loader前后仍各自重新校验，没有跨命令/请求授权缓存。
- 实际分发包测试覆盖必需initializer缺失，修正原合成fixture主动补文件而漏检真实包装的问题。
- CLI只给安全metadata；quote/grant/reserve不发HTTP，真正POST/GET才加载Key。默认off、observe_only禁写、到期或代码漂移不得新派发；原回执本地恢复/费用/交付另行校验。
- 本地取图每次都重验原query、task、scope、shot、manifest、policy和文件证明；缓存不跳过校验。恢复可定位原GET，不靠新key重查冒充恢复。私有准备脚本若在父分配后中断则fail-stop，不自动另建分配。

原生历史完整验证的CPU成本偏高。本轮运行仍持续推进，不能把慢误写成网络失败；后续先建立随frame/字节数增长的基线，再减少同一snapshot内重复的素材/费用/来源重建。不得用跨请求缓存、刷新deadline或少验历史来掩盖性能问题。
