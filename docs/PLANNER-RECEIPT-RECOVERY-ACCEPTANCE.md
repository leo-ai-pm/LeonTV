## 真实问题与证据边界

N02 在客户端等待 120.004 秒后无 HTTP 回执，保持 unknown，无被实际工具接收的分镜。17:50 最终平台导出另有一条关联错误：17:43:29、耗时 250 秒、524、行费用与用量均显示 0；令牌、分组、型号和时间形成关联，但导出没有原请求正文摘要及完整输出正文。

平台错误或费用记录、完整输出回执、执行状态恢复必须分别判断。该错误行不是丢失的 HTTP 正文，不足以恢复计划、补写用量、释放原风险或结束 unknown。平台账单可以确认其可核实范围内的费用，不能替代输出正文；未见账单也不等于免费。历史 M01-02 与 N02 的未知状态、原预留及调用次数保持原样，不追认或编造输出。

## 必须满足的行为

1. **先持久化，再通知。** worker 收到完整响应后，先将完整回执及其绑定信息私有、原子且持久地提交，再通知观察者。通知成功不能代替持久化成功；半写入、损坏或超限的内容不能被当作完整回执。沿用私有路径、访问隔离、容量和完整性保护，原始正文不得进入公共投影、日志或错误文本。
2. **分开两种期限。** CLI 的观察等待时间与原请求绝对 deadline 分开记录和判断。观察结束不等于请求取消、供应商未受理或 worker 已结束；worker 生命周期不依赖 CLI 等待或观察进程存活，仍受原绝对 deadline 与资源清理约束。重启、重开观察或 inspect 不延长期限、不产生新请求。响应到达与持久化完成跨越期限时的归类规则须预先固定并测试，不事后择取有利时间。
3. **迟到证据隔离。** 观察者结束后收到的完整回执作为隔离证据保存；超过原绝对 deadline 的内容同样隔离，并保留可核对的接收时间与绑定信息。均不得自动执行工具、结算、释放预留、恢复任务或继续付费。不得用迟到回执或错误覆盖已固定的 D12 诊断及旧状态；“发现证据”与“恢复执行”分别表达。
4. **inspect 严格只读。** 检查只读取已经持久化的证据，核对原 operation 身份、原请求 wire 摘要、原 deadline 和完整响应正文摘要；摘要算法及输入以原合同为准，不用近似时间、同型号、同一剧本或另一个任务替代绑定。缺失、错配、损坏、歧义或冲突均维持 unknown。检查不得写回历史、迁移 journal、改变授权、账务、预留、次数或状态，不调用模型或工具，不触发结算或放行。worker 采集新证据的写入与只读检查分离，不改写旧证据；通知与检查结果只提供安全摘要。
5. **重复与冲突保守处理。** 同一绑定、同一正文的重复回执只视为同一份证据，不增加调用或处理次数；冲突回执隔离并报告歧义，不采用“最后一份覆盖”来确认结果。有效证据也只说明可供后续另行核验，不能由 inspect 自动变成接受或恢复成功。
6. **供应商查询另设边界。** 当前 inspect 不联网。未来如需查询，只能使用已核实用途、权限和只读语义的接口，并验证与原操作的关联；未核实、缺失或无法唯一关联时停止并保持 unknown，不猜端点，不重发模型 POST 来寻找旧结果。

不修改 strict normalizer、工具接受判据、原 policy/wire/permit 摘要及正式生产禁用状态。具体接口、存储格式与兼容方案须在实现合同中明确，本文不虚构已存在的恢复 API。

## 先做合成故障验收

全部用合成响应和隔离私有状态执行，不使用真实配置、来源正文或付费服务。每项须提供故障注入点、落盘证据、重启后检查结果和请求计数；以下均为待执行用例。

| 编号 | 故障或场景 | 必须观察到的结果 |
| --- | --- | --- |
| R00 | 完整、及时、绑定与摘要一致的响应正例 | 先持久化再通知，独立读取可核对同一回执；inspect 本身不运行工具、不改变执行或账务状态 |
| R01 | 完整响应到达，持久化失败或提交前崩溃 | 不发送“已收到完整回执”通知；残片不被接受，保持 unknown；重启不补发模型请求 |
| R02 | 原子提交后、通知前崩溃 | 重启只读找到同一完整正文与绑定；不依赖通知重放，不自动执行工具、结算或释放预留 |
| R03 | 观察等待先结束，强制退出观察进程，worker 在原绝对 deadline 前收到响应 | worker 不因观察结束丢失回执；证据隔离可查，任务不自动继续；观察超时与绝对超时可区分，重新观察不另起派发 |
| R04 | 原绝对 deadline 已到后收到回执／错误，以及响应到达与持久化跨期限 | 按预定规则隔离；即使 HTTP 200、用量完整也不放行；原 deadline、诊断、unknown、预留及次数不被覆盖，无后续工具或付费 |
| R05 | 错 operation、错 wire 摘要、正文摘要不符，或绑定信息缺失 | 每种分别拒绝确认，保持 unknown；保留原证据，不猜测修复摘要或借用其他任务正文 |
| R06 | 相同回执重复到达，以及同一绑定下出现不同正文 | 前者证据幂等；后者明确歧义并隔离；两者均无新增模型 POST、工具执行或账务变化 |
| R07 | hard exit／重启、重复 inspect、重新打开 CLI | 额外模型 POST = 0；原来源、历史记录、授权、unknown、风险预留及调用次数保持基线，检查无持久化副作用 |
| R08 | 截断、损坏、超限回执，路径／符号链接或公共读取攻击 | 不将内容认定为完整有效证据；继承既有隔离与容量边界，原始正文及敏感信息不外泄 |
| R09 | 只有平台错误／零费用行、只有账单、无账单，或接口未经核实 | 不合成响应正文、工具输出或计划；不从记录缺失推出免费；当前 inspect 出站 = 0，未核实端点调用 = 0 |

各故障用例以该次原 intent 已落盘后的未知操作为比较基线，区分最初获授权的一次提交与恢复期间新增请求；不得通过重置账本、调用计数或另建操作掩盖重复提交。现有旧 journal 与来源 fixture 须逐字节核对不变。
