## 范围、授权与推进顺序

沿用原账户、scope／grant、原生日志、父资金证明及已有诊断归属。原 A 的 quote、activation、operation、descriptor／wire、capture／raw、规范 receipt、task 及全部原始证据保持不可变；不移动旧截止时间，不重封旧 raw 来制造新受理，不以更新旧 activation 的方式恢复权限。

新增**观察 quote／activation 或等价的显式原生观察记录**，绑定原 A 的上述精确身份、原 collector 证明、当前 source closure、控制／grant、原资金锚点、当前出生 checkpoint、披露 hash 和有限新 lease。新 lease 沿用既有观察合同不超过 24 小时的上限，另有更严限制时取严者。旧批准只能提供历史依据；新观察批准不能授予 POST、资金分配、撤销／重授生成 grant 或新 A／B。最新观察 revision、严格同意、相邻 checkpoint／CAS、撤权、代码漂移、历史及父证据变化均须在现有链路中核验，不能另建旁路账本。

本版对同一个原 A 只允许一份观察 quote／activation，不能再建 key 或重新 quote 续期。后续额外范围需要独立适用合同与验收，不代表本版可以续发观察批准。

若观察候选门禁需要历史例外，只能明确披露并冻结原三个 unknown，以及适用于所选原 A 的待核费状态，限定于该次候选校验；原记录和全局事实保持。不得按 ID 宽泛屏蔽其他类型记录、其他未决操作、新 unknown、费用冲突或超额。排除“当前已保存候选”时须精确等于该原查询，不得借同 ID 忽略其他候选。

本轮顺序固定如下；每一步的适用权限与证据独立检查，不由上一步成功自动启动下一步：

1. 统筹取得原平台任务／账户费用原始导出，做只读候选绑定。此处“平台观察”不等于对生成端点执行 GET，也不授予任何运行时写入。
2. 后端完成新观察合同及隔离验证，统筹验收精确当前代码和具体续行计划；形成有效观察授权。无有效授权时，只保留本地只读检查与获授权的平台观察，费用原生导入也不能绕过到期检查。
3. 在有效观察授权内幂等导入原 A 的精确费用观察；费用身份或金额未绑定，停止本轮后续 GET，不猜费用，也不以时间接近代替身份。
4. 统筹单独安排**最多 1 个新 GET 意图**，仅查原 accepted task，使用新 query identity／nonce 和固定幂等键。D46 在读 Key 前直接以 submitting 意图持久化；落盘即占用本轮唯一查询机会，哪怕尚未产生 claim 就崩溃，也只允许本地 recover，不补发 GET。它没有 reserved 首次补发路径，旧 profile 的既有路径仍按旧合同。所有历史查询累计，不因重启、换键、新 activation 或 lease 更新重置；原 policy 若剩余更少，以更严格上限为准。新 unknown／未决查询不自动续查，不重发生成。
5. 只有同任务规范完成回执与有效媒体来源证据齐备，且权限当前有效，才单独安排有限下载及诊断 artifact 登记；冻结来源、字节／时长上限、下载尝试上限和落盘位置。默认不自动下载，不以重新 GET 或生成刷新失效 URL。下载失败保留已有 accepted／completed 事实，记录未取得图片，不降格或伪造成功。

本轮没有自动轮询、重试、lease 续期、模型／端点／账户／Key 切换。任何额外 GET、下载重试或后续观察均不在本切片默认权限中；须先由统筹审查独立有限范围，不能重置本轮已用次数。新 POST、风险及资金增量持续为 0，B＝deferred。本地 paid_calls＝0 表示新生成额度为 0，GET 意图上限 1 单独计数；risk＝0 表示无新风险分配。这些约束不保证 GET 免费，也不保证平台对原 A 最终不会产生追加费用；无法在现有约束内解释的新费用或风险先停止并核对。

## 费用和状态的独立含义

精确费用关联按既有 exact-task fee 合同核对原 accepted task 与平台任务身份、原账户费用来源、适用模型／身份及稳定认领键，保留原始导出、来源、观察时间、币种、金额、单位和必要换算依据。token／分组按该合同适用来源核验，已提供字段矛盾须拒绝；不因 candidate 未独立导出这些字段而另加拒绝门。原 submit request-id 缺失时，只能采用经现有任务费用合同验证的 task 绑定；平台费用 request-id 与缺失的提交 request-id 不混同，candidate 的本地 task_id 与 provider_task_id 也不能混用。仅同窗日志、行号、quota0、任务 SUCCESS、HTTP200 或模型列表不足以认领费用。零费用也需要同样精确证据。

平台费用观察允许记为“已精确绑定的平台观察”，**final_bill_confirmed 仍为 false／未确认**；无最终结算证据不能称最终账单已核清、解除保留风险或增加可花余额。费用认领必须全账户去重，覆盖旧正式费用与新诊断费用；原首次费用事实不可覆盖。同一认领重放不增帧／不重复累计；冲突、重复跨任务认领及超额事实按现有规则记录和停止，不能忽略冲突以完成流程。

| 独立维度 | 本轮可接受的证据 | 不能由此代替的结论 |
| --- | --- | --- |
| accepted | 原 POST 精确规范受理回执与 task，历史已知 | completed、免费、已取图 |
| completed | 原任务有效 GET 的规范完成结果；控制台完成状态可另列平台观察 | 仅 accepted／pending／HTTP200 不算完成；控制台状态不冒充原生 GET 回执 |
| received | 对应完成结果的实际图片字节已取回、来源／哈希／格式／解码核对成功 | 只有 URL、下载开始或 GET 完成不算取得字节 |
| artifact | 原账户原生记录中的独立诊断 artifact 与精确字节／proof 唯一绑定 | received 不自动登记 artifact，也不构成正式交付 |
| fee_observation | 平台原始证据精确绑定并经原生费用规则认领；导出与导入分开记录 | 不等于最终账单、不证明图片质量 |

各维度可同时处于不同状态。缺证据用 unknown／pending／not_run 的适用含义说明，不把“已受理但费用待核”改成提交 unknown；原三个 unknown 不因原 A 有进展而清除。

实现候选的原生摘要在 artifact 未登记时以 received=null／not_recorded 表示“原生未登记字节”，不能解释为已下载或下载失败。本地已下载但尚未登记的 received 字节事实由独立下载证据列出；原生登记精确字节后才能报告 true／native_artifact_bytes。
