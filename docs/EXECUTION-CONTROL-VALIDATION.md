## 实际记录回放

原始平台导出及原生已接受费用通过新的 `register_legacy` 注册到独立 D27 sidecar。第一条保留原历史筛选序号别名，其余稳定身份保持；每条重新校验原 operation、wire、回执、用量、账户来源及导出摘要。重复导入仍为 **4 份导出、4 条已应用记录、0 条待应用**。没有将这些历史费用再次写入 native journal。

平台费用观察仍为 **¥0.038086**，不代表最终供应商账单。原 100 元授权、父账本 42 条记录及 **¥75.37 风险占用**保持原样；风险不是已消费金额。本轮新增费用为零，旧未知没有被解除。

对额外挂载的实际检查将费用目录公开为静态目录，Brief／Planner／Execution 三路全部返回固定 `CONTROL_UNAVAILABLE`。整个回放前后，原 D26 journal、父账本及 **418 个受保护文件**摘要完全一致。新控制文件、独立 sidecar、回放脚本与用户正文均留在忽略的私有证据目录，不进入公开仓库。

## 修复与剩余工作

独立审查发现并修复两处问题：CLI 导入原 `core` 包会提前加载旧工作流和模型配置，现改为按需导出并保留旧类名兼容；恢复动作提交 worker 后与迟到费证存在门控时序窗口，现以同一锁协调，避免费用已记录但后继交接丢失。原生 `observe_fee` 的默认行为保持兼容，服务端可明确指定只记账。

费用数据仍由操作端取得土豆原始导出；本轮没有实现平台账户自动登录／日志拉取、操作员配置 UI 或多供应商费用插件。合成恢复通过与旧真实数据回放通过，并不等于新启用范围已经真实生产验收。

下一项是将实际接受的四镜版本交给素材角色，建立角色／场景定型、逐镜图像引用、独立视觉审阅与局部返工的正式任务链。继续继承原来源、版本、累计预算和费用门禁。历史三镜媒体不得直接充当本次四镜计划的交付；视频通道恢复、真实内容改稿／复核及最终人的版本验收仍分别待办。

代码与文档仅本地提交，本轮未推送远端，未重启共享前后端服务。
