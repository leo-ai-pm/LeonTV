# 四角色统一执行验收 · D25

2026-10-24。本轮将 Planner、独立 Reviewer、受限 Repairer、独立 Rechecker 接入原 `ExecutionRuntime`、报价授权、累计账户额度与回执处理。一次显式启动后自动交接，使用同一个任务锁、worker和账本；模型HTTP响应通过合成传输验收。

这是受控执行代码的产品集成，**尚未完成真实四角色协作验收**。正式生产和默认回执采集继续关闭；没有新增真实模型、图片、视频、音频或费用。[接口与边界](./PLANNER-ROLE-EXECUTION-API.md)。

## 已交付

- 服务端显式 `bounded_revision_v1` profile；首次报价冻结workflow、normal来源模式和执行环境。完整四角色／外发资料／角色上限进入报价披露与新授权，旧任务和旧授权不静默升级。
- 原账户、任务与授权共同限制所有角色的累计预占、本地计价和调用次数。总意图最多6次，首审、内容改稿和复核各最多1次；换授权、角色或重启不重置。
- 原单次HTTP传输与sink重新核对角色、绑定摘要、context／wire、许可和可信输入上界。原回执归一和计价规则保持，未提供经验风险模式或伪造可信计费边界。
- 首审接受结束v1；有明确允许范围的拒绝才改稿，合法且实际变化的候选才追加v2。独立复核使用完整来源、v2和旧问题，终态后不自动生成v3。复用既有纯合同，D18／D23／D24五个受保护模块字节不变。
- 计费回执有效但内容非法仍计价并停止；未知、截断或不完整回执保留预占。暂停／撤销阻止后继，在途回执保存，恢复不重发或重复结算。
- 新profile的源、环境、账户上限、报价／授权引用、操作身份、角色绑定、首次raw和settled金额受历史约束；读取最终状态仍从零完整重建语义。
- 前端显示四角色范围、共享账本、逐操作角色／回执、当前版本及首审／复核结论。新模块只读，不增加角色之间的确认按钮。环境不再借当前策略推断已有执行；旧执行从自身历史报价保守推断，无旧文件迁移。

`quality_status`仍是 `not_reviewed`，`provider_bill_confirmed`仍为false。一次文字判断、媒体质量与人工终验分开；合成接受不是真实质量通过。

## 修复与独立审查

独立审查在首次grant记录中发现三处锚定不足：引用另一任务报价、错误scope、错误policy hash，在重算外层链后曾未被拒绝。现验证其确切报价、任务／来源、策略／披露、scope、累计上限与期限；也核对quote的策略重建、预占及账户绑定，以及操作许可全链引用。修复后同一七项重哈希攻击全部拒绝，实际read_only／transaction入口均返回 `CORRUPT_STORAGE`，原文件字节不变。

七项包含上述三类、账户上限提高、submitting预带raw、首次received回执改写、settled费用改写。它们是存储完整性负例，不表示公开API允许客户端直接提交这些内部记录。

逐帧重建曾重复检查已经验证的旧角色上下文和报告。本轮改为同次读取内的增量归纳：未变record保留对象身份，变化delta按值复制并重新检查；最后快照仍从零完整核对角色、来源、context、工具、费用与版本。不缓存跨请求私有状态，也不放宽原15秒联调等待阈值。
