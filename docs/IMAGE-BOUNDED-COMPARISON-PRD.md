2026-10-28（Asia/Shanghai）。状态：**产品合同准备稿，待统筹验收；设计／合成／真实验收初始均 not_run。** 后端负责实现与技术证据，统筹负责集成验收、资金／运行计划及 Git；PRD 写完不代表开发验收通过。

## 目的与当前基线

用一次**探索性、最多两次生成 POST** 的有限对照，检验“历史可受理请求在当前入口的表现，与产生 403 的请求是否不同”，减少无信息的盲重试。不能保证定位根因，也不以不断重试证明 Agent 自主能力。最终目标仍是总控在授权内委派、独立审阅和局部返工，人对当前最终产物验收。

**当前最小切片是 A 一个独立诊断 POST 的资金→执行→恢复／结果隔离完整链，不是仅报价冻结，也不预授实际调用。** A 使用历史第二镜控制内容、同原账户、全新诊断身份和显式增量；B 当前为 deferred/not_run，仍缺独立资金、依赖、旧同镜上限下的合法准入及适用实现验收。A 单步通过不等于完成 AB 对照，不能反复新建 A 凑样本；只有 A 已规范受理、精确费用确认及其他门禁齐备后，统筹才决定是否安排 B。A 未受理即停，任何新 unknown 仍立即停止后续付费。

依据：[D44 API](./IMAGE-FAILURE-DIAGNOSIS-API.md)、[D44 验证](./IMAGE-FAILURE-DIAGNOSIS-VALIDATION.md)、[D43 API](./IMAGE-RETAINED-UNKNOWN-API.md)、[D43 验证](./IMAGE-RETAINED-UNKNOWN-VALIDATION.md)、[自主协作目标](./AUTONOMOUS-COLLABORATION-GOAL.md)。以 D44 最新事实为准：原 79 帧、正式图集 2/4、三个 unknown；图片 POST 意图 5/5 已用，GET 3、交付 2、费用记录 2。原 100 元授权持续，82.37 元／54 次是保留风险与保守次数包络，不能当消费、可花余额或现成资助位。旧 runtime 批准因代码变化不可用，当前 dispatch/query 均 false。

D44 的 303 项是相关测试，非全套；真实 ENTRY＜120 秒性能验收未过。HTTP403 仍为 unconfirmed，无可用受理身份，不能确认未执行／零费；通用鉴权成功不证明生成路由健康。D45 不改旧分类、截止时间或必需权限检查来凑通过。

| 不变项 | 同一原账户／既有凭据、模型、端点、方法、客户端代码、请求结构、画幅／分辨率／质量和参考编码规则；冻结准确请求字节／参考字节及差异路径。新 operation、nonce、累计序号、期限等身份按新计划生成，不伪造旧身份；若另有上游输入差异，须披露或判不具可比性 |
| 主要观察点 | **POST 的规范受理结果**：精确有效的受理身份、确证拒绝或 unconfirmed。受理、任务完成、交付、费用确认分别记录；仅 task_id 字符串、pending 或 HTTP200 不等于完成／成功出图 |
| 顺序与上限 | 总体固定 A 后 B、串行，最多 2 POST；当前 A 单步范围最多 1，B 不可执行。未来 B 须 A 已规范受理、精确费用确认及其他门禁齐备，再由统筹决定，且独立满足资金、准入与适用实现。A 未受理即停，B 保持 not_run；原门禁若还要求完成／交付／查询证据，不能为凑对照跳过 |

若无法重建可比的精确输入，或这一比较本来无法区分所声称原因，先只读核对并记录局限，不为填满两个名额发请求。同账户／模型／端点保持不变意味着本轮没有直接操纵“通道”；顺序、时间波动、上游路由及内容与通道交互仍可能解释差异。

下表成对结果仅规定总体设计的推断上界，不开放当前 B；即使 A 有确定结果，当前范围也只能记录 A 单样本、B 未执行，不能宣称一对已完成。

| 本批观察 | 允许结论；禁止推断 |
| --- | --- |
| A 新 unknown（含 403-unconfirmed） | 停止，只有一个未确认样本，B 不执行也是正确结果；不能判 Key 错、未执行或零费，不能另建批次补齐对照 |
| A 有确定回执但费用／其他前置证据不足 | 保留已知回执事实，只读核对；B 不执行，不能以同窗 quota0 或猜测费用续行 |
| A、B 均受理 | 只说明这两次在该测量点可受理，未复现原症状；不解释历史 403、不证明稳定成功率或通道永久恢复 |
| A 受理，B 确证拒绝 | 本次样本表现不同；内容选择性、时间／路由等仍混杂，不能确认内容因果或唯一根因 |
| A 确证拒绝或未规范受理 | 本合同不运行 B，仅有 A 单样本；不能据此判 Key／通道根因或零费，也不能宣称得到双拒绝对照 |
| B 新 unknown | 仅保留 A 的局部确定事实及 B 的未确认事实，立即停止后续付费；不能把 B 归入确证拒绝 |
| 未触发或未满足继续条件 | 相应步骤／分支记 not_run，不用历史或合成结果补成真实一对 |

上述“受理”结论不提升为完成、已核费或视觉通过；确证拒绝也不自动表示零费。

## 阶段、推进条件与界面边界

先完成本合同与报价／证据冻结，再完成 **A 的明确资金增量→原生一次执行→重启恢复→费用与结果隔离完整链**，由统筹逐项验收；只交付报价冻结不能称 A 最小切片完成。实现／合成验收与真实 A 执行分开，门禁齐备前不得真实测试。适用同意／批准指原用户授权内针对确切版本和子范围的运行记录，不是让用户重新批准 100 元。A 与整批对照分别验收；未来 B 必须 A 已规范受理、精确费用及其他门禁齐备，且资金／准入／实现另获统筹确认，不因 A 完成自动推进。A 未受理即停。无法区分就明确记录，先只读核对，不循环试错或直接恢复正式生成。

以下情况保持只读：无新资助／有效批准、无法精确重建可比输入、费用未绑定、任何新 unknown、旧证据漂移或期限／身份不符。只读指本地验证及获授权的平台观察，不等于调用生成任务 GET；没有确切任务身份或查询权限不能猜测查询。

原 100 元不重复向用户申请。正常技术报价、统筹验收与中间推进由总控／专项窗口承担；仅确需超出现有用户授权、缺少不可替代的用户决定／外部事实、必要外部证据确实因会话失效无法恢复，或最终当前产物接受／退回时才请用户参与，说明最小所需事项，不惯性索要 Key、登录或客服回复。当前没有需用户重复批准的事项。

前端本轮**不实现 UI**；将来至少分别展示：原批准是否当前有效、诊断批次／变量及已资助剩余槽、历史与本批次数、三个保留 unknown、已有五项 response_diagnostic、费用“已精确确认／待核”、风险“保留风险，非已消费”、结论“探索性观察／无法区分”、正式图集 2/4、视觉及用户终验。摘要不得出现“403＝Key错误／免费”“对照成功＝已修复”或据此开放重试；不展示 raw、凭据或签名媒体 URL。

交付完成只表示需求边界清楚、可由后端按 BC01–BC09 映射；设计验收、开发验收和真实效果均须各自证据，不能由 PRD 自评替代。
