未来明确授权、出生前opt-in的正式镜头，在原query取得规范completed回执后，由现有执行链自动完成一次有限下载、完整校验、耐久私有保存及原delivery登记。用户通过现有 `GET /api/planner/tasks/{task_id}/execution/media` 查看结果；刷新只读取本地事实，不发起模型、provider查询、下载、登记或恢复。

本轮沿用现有正式图片permit的首帧v1协议；未扩展后续图片版本、视频或真实生成启用。普通正式profile已取得隔离原生证据，复杂retained-unknown continuation仅有接线与既有门禁依据，不称本轮已完成其全链实测。

## 用户可见状态

状态取自当前任务、镜头和准确operation的严格本地投影。接口具体字段由后端API冻结，前端严格解码后再呈现；本表不要求另建状态账本。

| 用户状态 | 最低事实依据 | 必须区分的情况 |
| --- | --- | --- |
| 生成中 | 当前读取确认原生任务处于已知处理中 | unknown、过期响应或读取失败不能伪装仍在运行 |
| 已生成待保存 | 规范completed成立，但尚未确认本地完整保存／登记完成 | 远端URL或completed本身不证明已取得图片 |
| 已保存 | 新正式保存链的准确字节／proof本次核验有效，且原delivery准确关联 | legacy delivery、诊断artifact、历史saved元数据不单独满足 |
| 保存失败 | 明确接收／校验／存储失败，原因可准确分类 | HTTP404只说明该次资源获取失败，不推断链接过期或上游根因 |
| 结果待确认 | unknown、当前可用性未验证、必要保存／登记被权限或期限阻断、本地登记未完成或读取失败 | 可另列“历史已保存／已登记”，但不能保留当前已验证成功外观 |

“生成失败”等已有确定原生结果保留，不强行折叠为保存失败。当前读取不可用时清除当前核验标识；若保留历史内容，必须明显标注历史／未确认。默认卡片显示镜头、主状态和一句可理解说明；operation、阶段、HTTP状态、错误码、历史登记与当前文件核验按需展开。安全投影不泄露Key、签名URL、raw回执或任意本地路径，不新增未经授权的图片读取／预览能力。

lease到期不抹除已保存／已登记事实；只读核验若仍能证明准确文件当前可用且delivery已登记，可继续显示该保存事实，同时注明执行权限状态，不能据此继续外部动作或补写。保存事实、当前文件核验与写权限分开判断。
