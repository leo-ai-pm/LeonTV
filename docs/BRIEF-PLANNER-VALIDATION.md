## 交付范围

正式 `/creator` 的 A「放映室」可将明确的已保存 Brief 版本冻结成独立规划任务，查看状态、来源版本、安全事件与结构化镜头计划。原简报后续修改不改写旧任务；未保存编辑、历史版本、冲突或保存结果未决时阻止新建。

正式 `/api/planner`、私有持久存储、跨进程锁、幂等创建/动作、白名单工具、严格计划校验和有界反馈循环使用实际实现。正常任务持久等待授权；独立 `offline_test` 入口只替代模型响应，创建后显式启动，可验证成功、坏计划修正、非法工具、步数上限和响应未确认。

本版两个工具为 `read_frozen_brief` 和 `submit_shot_plan`，无任意代码、文件、URL、搜索或媒体工具。校验15秒、9:16、来源绑定、唯一镜头与无环依赖；最多6次模型步骤、2次错误。`plan_ready` 仅表示结构合格，`quality_status` 仍为 `not_reviewed`。

## 独立验收与回归

验收使用排除真实配置、剧本、运行数据和媒体的隔离副本，仅合成输入。原预览服务与用户页面未重启。后端进程设出站阻断；真实模型、付费与媒体生成均为0。

- 实际 HTTP：正式任务等待授权且调用步数为0；创建键跨模式唯一，动作键绑定原动作与原 revision；同键重放返回当前状态与原 applied revision。
- 来源冻结：仅制作要求/预算变更时，剧本 hash 不变，完整 snapshot hash 变化；旧任务仍返回旧要求、旧预算和原样正文。摘要、详情、查回与事件不含冻结正文，完整正文只通过显式 source 读取。
- 实际浏览器：dirty 门禁、v2 编辑不改变 v1 任务、手动读取冻结正文、离线 repair 经3步/1次错误后结构合格；刷新恢复选中任务和计划，不自动取全文。
- 实际断网：创建与动作均保存原键和原参数；查询动作状态不会冒充动作键已确认，后续原键重放可恢复。浏览器持久记录不含剧本或制作要求。
- 代码审查与回归包括异常输出、存储损坏、静态树双向隔离、符号链接和旧 D06/D07 兼容；具体最终检查结果见下方。

## 已发现并修复的边界

- 响应未确认后暂停应保留 `MODEL_RESPONSE_UNCONFIRMED`，同时保留未决调用且禁止强行续调。
- 深层 JSON 即使低于字节上限，也可能触发解析递归错误；须返回安全的工具反馈并消耗修正次数，避免重复解析同一回执而无法推进。
- 历史链需要独立持久 head 与尾帧一致性检查，防止单独删除最新帧时丢失成功动作回执并再次消费其键。此检查不宣称防止整个合法旧文件被回滚。
- 文本适配器输入字节门禁检查实际序列化发送体；新规划区交互目标按实际375px浏览器尺寸复验44px。
